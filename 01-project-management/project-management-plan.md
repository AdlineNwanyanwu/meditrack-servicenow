
# MediTrack — Project Management Plan

## 1. Project Overview

**Project:** MediTrack — Medical Equipment Management  
**Platform:** ServiceNow  
**Program:** ServiceNow RiseUp  
**Team:** Langston Team — Group 2  
**Team Size:** 5 Members  
**Project Manager:** Adline Nwanyanwu  
**Status:** In Development

MediTrack is a team-based ServiceNow application designed to support medical equipment tracking, repair request management, and preventive maintenance activities.

## 2. Project Management Objectives

- Coordinate project activities across five team members.
- Establish clear responsibilities and deliverables.
- Monitor project progress and development milestones.
- Identify and communicate project risks.
- Support collaboration and integration of application components.
- Coordinate testing and final project demonstrations.

## 3. Project Scope

### In Scope
- Equipment Management
- Repair Request Management
- Preventive Maintenance Tracking
- Work Order Management
- Service Catalog Configuration
- Workflow Automation
- Role-Based Access Control
- Reporting and Dashboards
- Testing and Documentation

### Out of Scope
- Integration with live hospital equipment
- Processing real patient information
- Production deployment in a healthcare organization
- External vendor billing or payment processing

## 5. Project Phases

### Phase 1 — Initiation and Planning
- Define the business problem.
- Establish project goals and scope.
- Identify stakeholders and user roles.
- Assign team responsibilities.

### Phase 2 — Application Design
- Define custom tables and relationships.
- Design forms and lists.
- Plan repair and maintenance workflows.
- Define security requirements.

### Phase 3 — Development
- Configure ServiceNow application components.
- Build custom tables and forms.
- Configure Service Catalog items.
- Develop automation and notifications.
- Create reports and dashboards.

### Phase 4 — Testing and Validation
- Test individual application components.
- Validate user access permissions.
- Test repair and maintenance processes.
- Identify and resolve configuration issues.

### Phase 5 — Final Demonstration
- Prepare the application demonstration.
- Review completed deliverables.
- Present application functionality.
- Document project outcomes and lessons learned.

## 6. Communication and Collaboration

The project management approach emphasizes:

- Clear assignment of responsibilities
- Regular progress updates
- Communication of blockers and dependencies
- Coordination between team members
- Documentation of project decisions

## 7. Risk Management

| Risk | Potential Impact | Mitigation Strategy |
|------|------------------|---------------------|
| Development delays | Incomplete deliverables | Prioritize core functionality |
| Configuration conflicts | Application errors | Coordinate changes and use update sets appropriately |
| Integration issues | Workflow failures | Perform component and end-to-end testing |
| Access control issues | Unauthorized or blocked access | Test roles and ACL configurations |
| Limited project time | Reduced scope | Focus on minimum viable functionality |

## 8. Success Criteria

The project aims to demonstrate:

- Functional equipment tracking
- Repair request submission and management
- Preventive maintenance tracking
- Automated workflow actions
- Appropriate role-based access
- Useful reports and dashboards
- Successful end-to-end testing
